## 2. Gaps — decided

- **G1 `ledger` id is on two routes by construction.** `OverallLedger.tsx:40,66` renders `id="ledger"`; `nfl/page.tsx:884` also. Metric #5 lists `ledger` as a singleton across the four routes → unsatisfiable without a rename the spec forbids. Decision: keep both, drop `ledger` from the metric #5 set, note that no redirect targets `#ledger`.
- **G2 The "next board" line cannot be derived as specified.** Spec `01:119`: `latestBoard.week + 1` plus "earliest `kickoffUtc > now` in `nfl-slate.json`". Measured: the slate window is `2026-09-08T15:59Z → 09-16T12:20Z`, kickoffs `Thu 09-10 00:20Z → Mon 09-15 00:15Z` (week 1). On Saturday evening the earliest future kickoff is **Sun Sep 13 17:00Z — a week-1 game**; the line would print "week 2 board publishes 12h before Sun Sep 13 1:00 PM ET". Decision: only use kickoffs strictly later than the latest board's max `kickoffUtc`; when none exist (the normal case until the daily refresh crosses the week) print the dateless copy "NFL week 2 board publishes at least 12h before its first kickoff." Unit-test with the committed wk01 board + slate → no date.
- **G3 State (c) has no data source.** The stale state needs the odds snapshot's `fetchedAt`; `DashboardData` never exposes it (`dashboard.ts:394-432`; `loadOdds` `:493-495` discards it) and the list's agent rows come from Turso, not the snapshot. Decision: `live-actions.ts` (already `node:fs`) reads `fetchedAt` from `latest-odds-api-{basketball_nba,baseball_mlb,basketball_wnba}.json` → `oddsFetchedAt` (max); `slateHasToday` = any `data.slate[].commenceTime` on today's ET date. Stale = `oddsFetchedAt` > 36h old OR `!slateHasToday`. In that state the empty sub-line must **not** say "Nothing cleared the 6% floor" (a false explanation); it prints "The desk has not run on today's slate · lines last refreshed {ET} · analyst last ran {rel}" in `--hold`. NFL rows still render (the board carries its own `publishedAt`). No second `dashboard.ts` change.
- **G4 The 8 PM ET hole.** `loadTodaysPicks` keys on `createdAt ≥ UTC midnight` (`dashboard.ts:981-989`); `lastNight` only admits `gameDate < now` (`:1556`). A 22:30 UTC pick for a 10:10 PM ET game is on neither list from 8 PM ET until tip. Decision: the live list also admits `data.lastNight.games.picks` rows with `outcome === null` and `gameDate + 4h > now` (recovers in-play rows after tip; already loaded; dedupe by id); the pre-tip window is documented in a code comment and stays LATER 1. `gameDate` is a real start instant — `AgentPick.gameDate DateTime` (`schema.prisma:109`) is set from the analyst's `gameTime = commence_time` (`analyst.ts:152,159,185`) — so the 4h "in play" state is valid for games and props.
