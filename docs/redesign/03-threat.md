## 0. Stakes

What it can do is **lie quietly**: ship a green build whose panels render empty or print a false placeholder in production (tracing), send the X audience from an old `/#props` link to a page that ignores the fragment, make `/nfl` — the page Nate posts — pay ~25 Turso round-trips per visit if the shared header carries data, leak NFL units onto `/` in violation of pre-registration Amendment 1, or re-introduce the measured "NFL question answered with an MLB pick" misroute on `/nfl`. ## 2. Abuse and reliability (proportionate)

- **A1. Fan-out with ISR intact.** A crawler hammering `/desk?x=<random>`: the app-router static cache keys on the pathname; query strings are ignored unless a component reads them (none do — S13). One regeneration per route per 300 s regardless of request volume. Fine.
- **A2. Fan-out with ISR lost.** See S13. The only realistic way to lose it is the shared header carrying `data` onto `force-dynamic` `/nfl`, or a dynamic API sneaking in. AC3 catches both.
- **A3. Missing data file at build.** Every file-reading panel is guarded and degrades to null/fallback (S2 list), so `next build` cannot fail on data — which is exactly why S2 is silent. Two panels degrade to a **false statement** rather than an absence (`NflWeek.tsx:78-83`, `nfl/page.tsx:213-226`); the rest hide. `revalidate = 300` pages are prerendered at build, so a file missing from the build tree shows the placeholder for ≤300 s, same as today.
- **A4. `/api/chat` surface.** Unchanged: body cap, session cap, per-IP cap and scope validation live in the route (`route.ts:3-17,100`). No new attack surface from mounting the island on more routes; the panel already posts from two.
- **A5. Redirect loops.** `/picks → /` is one hop. The S3 client hop `/ → /desk#…` must be mounted on `/` only and `/desk` must never redirect back; a `#tonight` target of `/` must be handled as "strip the hash, stay" (no navigation), or it loops with itself.

Concurrency (Kingsbury pass): there is no write, no idempotency key, no multi-system commit in this change; the only interleaving of note is ISR regeneration racing a data-commit deploy, which already exists today and resolves at the next 300 s tick. Nothing to add.

Operability (Majors pass): the failure that will page nobody and mislead everybody is S2 — a green build with an empty `/desk`. There is no log line for "panel hid because the file was absent" (`existsSync → null` at `NflWeek.tsx:14`; `catch → null` in the books). The builder should not add logging to untouched panels, so the guard has to be the build-artifact check (AC4) plus a post-deploy eyeball of each route. `/nfl` already logs a present-but-unparseable file (`nfl/page.tsx:93,115,144`); that behaviour is kept by not touching those functions.
